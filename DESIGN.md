# Yaundromat · Silliman Basement

The room follows the supplied Entryway M sketch: ten washers (two at the top, four on the left, four on the inner right) and four dryers in the far-right column. Machine IDs and physical positions live in `src/lib/silliman.ts`. The plant remains, horizontal cubbies occupy the bottom-right corner and open a centered popup of recorded machine moves by cubby, and the entrance is at bottom left; the folding table and washer mascot are removed from the map.

## Visual system

The liquid-glass treatment uses cool translucent surfaces, subtle highlights, Mallory typography, a blue glass navigation dock and blue primary actions. `liquid-glass.css` is loaded after structural styles in the root layout. Washers use pale blue glass shells and dryers use soft yellow glass with subtle contrast to separate both from the floor; status color lives in the inner circle and text. A conic-gradient pie shows remaining cycle time, paired with a countdown below. Pickup Window uses an orange countdown pie behind a legible hourglass icon, alongside its numeric countdown. The active navigation pill slides between tabs with a shared-layout spring and switches instantly for reduced motion. Active and inactive tabs keep the same navy text and weight, using a lighter blue selected surface; icon hover backgrounds are omitted. A visible “Yours” badge and blue outline mark owned loads. Each outline traces around its own machine without moving between tiles. Selection uses a smooth dark overlay only while its popup is open, then clears; light machine shells retain translucent gradients and bright glass highlights. Available and completed states retain their status icons.

The four status colors are light green (available), blue (running), orange (Pickup Window) and dark green with a laundry basket (okay to move). Almost done and Done are no longer lifecycle states. Text and accessible names accompany colors. Every machine remains at least 44 × 44px at supported widths, including 320px. Reduced motion is respected, and opaque dialog surfaces are supplied for reduced-transparency preferences.

## Home and starting laundry

The page starts directly with the room card and a local time-of-day greeting for Timothy. The compact room heading shows Silliman Basement, Entryway M, availability and **Do laundry**. That action opens a centered Do laundry dialog with manual machine entry and QR scanning. Below a plain divider, the dark-blue See what’s free button transitions to Washer, Dryer or Both choices, then opens the full-screen map filtered to available machines of that type. If none are free, it opens the full-screen list at the first nonempty tier: Okay to move, Pickup Window, then Running. That fallback sorts by next availability across types, and follows lifecycle changes until filters are manually changed. Explicitly choosing a type priority can still regroup the list. A Back action returns to entry; switching steps stops the camera, moves keyboard focus and respects reduced motion. Filters offer machine type and status. The map/list card contains one compact top row: full screen, Map/List, sort and filter. At narrow phone widths, the Map/List toggle uses labeled icons to preserve touch targets. The room name and Entryway M badge share one line. Smaller utility icons flank a precisely centered Map/List switch. The legend and machine-type key are removed. Filter and sort dialogs open centered. Sort has two independent radio groups: Machine number or Soonest available, and Washer first or Dryer first. Machines are grouped by the preferred type, then ordered within each type; both choices remain selected. The map has no custom zoom, pan or reset controls. Both map and list can expand to the full available screen using the expand button. The same room card animates from its current bounds to the screen edges and back, with an instant transition for reduced motion. The toolbar stays visible above the scrolling content, and switching modes or exiting full screen preserves filters and sort order. Escape exits full screen after any open machine/filter dialog is dismissed. Exiting returns focus and scroll position to the original expand control.

Manual entry accepts IDs such as W03, W3 or Washer 3. QR codes may contain a valid machine ID or a URL with `?machine=W03` (or a final path segment containing the ID). Codes only select machines in this room; scanned URLs are never navigated to. Camera frames are decoded locally with the dynamically imported `jsqr` library. Camera access requires HTTPS or localhost and user permission. Permission errors leave manual entry usable. Camera tracks stop on dismissal, successful scan and error.

The soonest list ranks truly available machines first, then occupied machines by cycle end plus the pickup window. These are estimates; completed laundry is not marked available until collection or a move is recorded. Map filtering keeps physical slots fixed.

## Machine popups

Native centered dialogs contain the machine name, status, a pie/time summary, cycle duration, started and estimated finish (or finished) timestamps, the contextual start/collect/move action and an alerts toggle. Native modal behavior contains focus, makes background content inert and supports Escape; focus returns to the trigger or quick-start button. Short screens scroll within the dialog. The previous description, instructional paragraph, decorative copy and View on map action are removed.

A wash timer is 30 minutes and a dry timer is 45 minutes. Pickup Window countdowns appear on machine tiles, lists, load cards and popups. Once it expires, only your own load indicators turn red; neighbors remain dark green. List rows, load cards and alerts show live timing: remaining cycle time, or time sitting since completion alongside the Pickup Window countdown when applicable. Ready machines show their cycle duration in list summaries. Map tiles retain their compact cycle/pickup countdowns and status labels, without sitting times or ready-cycle durations. Finished-machine popups also retain the stopwatch. Alert history labels current machine timing separately from notification age and timestamp. The pickup window is five minutes from cycle completion; Pickup Window starts immediately at cycle completion and lasts the full five minutes. Starts are local simulated timers, not physical machine commands.

## Alerts and persistence

Home, My loads and Alerts share the same frosted load card: a pie timer, machine name, remaining time, detail chevron and separate alerts toggle.

The third tab is **Alerts**, split into **Your loads** and **Other machines**. Starting a load enables its alerts; the machine popup or Alerts page can turn them off. Watching any other machine adds it to the other section. Completed cycles generate a finished notification, and collection/moving generates a separate available notification. Notifications are deduplicated per machine, cycle and category. Each notification persists its own read timestamp. Opening Alerts leaves notifications unread; clicking one marks it read. The Alerts tab shows the unread count. Legacy read state migrates from the previous last-viewed timestamp.

`alerts.ts` derives events from persisted watch snapshots. `laundry-storage.ts` validates the 14-machine room before restoring state under `yaundromat-silliman-v2`; the previous room’s saved prototype remains separate. Existing Almost done watch snapshots migrate to Running and Done snapshots/history migrate to Pickup Window without resetting machines or duplicating completion alerts. Reloading preserves watches and history and catches up completed cycles. These are in-app alerts, with no push or backend connection.

My loads includes a History disclosure, collapsed by default, with persisted history in list and local-date calendar views, plus completed-load totals, wash/dry counts and cycle hours. Records capture tracked starts, scheduled finishes and collection times; legacy saves retain their loads and seed history from currently owned cycles. An active bell means alerts are on; a crossed bell means they are off.

The My loads page keeps prototype controls in a collapsed disclosure. Fresh/reset demos include two unread alerts and a completed W05 load moved to Cubby B. Simulate my load moved to Cubby B finishes and moves a current owned load, frees its machine, records its destination in history and cubbies, and adds an unread notification. Skipping five minutes advances all machine and watch timestamps together so both own-load and watched-machine alerts can be explored.

## Phone PWA

The washer-and-Y logo in `public/icon.svg` uses navy outlines, three distinct blue water sections separated to the drum edge by a white Y, and a pale glass background. `node scripts/build-icons.mjs` regenerates its app and Apple PNGs plus the safe-area maskable version. The manifest uses a stable root ID, standalone display, light blue theme/background, standard Android icons, a maskable icon and an Apple touch icon. Standalone layout fills the phone height and respects all safe-area insets. Installation uses the browser menu, with no in-app install control. The translucent bottom dock floats over all pages, including full-screen map and list views. Scroll padding keeps the final content reachable above it, and the dock stays inside the desktop preview.

The production build generates a versioned service worker from `src/pwa/service-worker.js`. Installation atomically precaches the home document, build chunks, referenced fonts, manifest and icons. The matching document/assets are served together from that version until an update is accepted. Only this static prototype shell is cached; API calls, other routes and Next RSC requests are not intercepted. An offline indicator makes connectivity visible.

`PwaControls` registers the worker in production, checks updates when returning online or foregrounding, and offers an explicit Update app action. New versions finish caching before activation. Activation clears only old Yaundromat caches and reloads clients; local loads and watches remain untouched. Foreground/pageshow listeners also refresh cycle timestamps immediately. Offline use does not introduce background notifications or a server connection.
